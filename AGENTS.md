## Project Custom Agent Guidance

### Project Purpose

Concierge provides personal agents, such as ChatGPT and Codex, with pre-authenticated access to the owner's accounts and capabilities that native integrations lack or expose incompletely.

- Keep this a private, personal MCP server, not a multi-user integration platform.
- Prefer broad programmatic API access over narrowly curated actions when it serves the owner's needs; keep credentials and authorization boundaries server-owned.
- Supplement native agent integrations rather than duplicate capabilities they already provide adequately.
- Keep connectors minimal and put shared authentication and reliability behavior in reusable infrastructure.

### Integration Design Principles

- Prefer thin, pre-authenticated adapters to official APIs or platform bindings. Connectors should provide access and provider-specific behavior, not recreate the provider's product or implement agent workflows.
- Preserve native API paths, query parameters, request bodies, response shapes, pagination, and attribution where practical. Let agents compose calls and process results in Code Mode; transform data only for a concrete security, compatibility, or output-size requirement.
- Keep discovery compact. Prefer a generic request method for broad REST APIs when a full SDK or generated OpenAPI catalog would add substantial schema noise. Use richer typed methods when they materially improve usability without excessive context cost; models can consult official endpoint documentation.
- Keep credentials, trusted API origins, scopes, and account identities server-owned. Support writes and deletes when intended; do not impose read-only limitations merely because callers are agents. Additional endpoint restrictions should have an explicit security, provider, or product rationale.
- Reuse shared request, validation, and authentication infrastructure and proven libraries. Keep only provider-specific contracts, authentication details, and error/replay classification in connectors; avoid parallel retry loops, speculative abstractions, and credential fallbacks.
- Make capabilities and limitations discoverable in method descriptions, not only connector-level instructions. Keep connector hints and MCP annotations aligned with actual support; distinguish API access from external-content search and interactive browsing.
- Keep integration tests credential-free and repeatable, covering native request/response behavior, credential isolation, and failure handling. Use a live read-only MCP call to verify real credentials and provider setup when available; do not treat mocks as proof of production access.

### Implementation Guidance

- Preserve the vendored C3 block above unless intentionally refreshing it from a newly generated Create Cloudflare scaffold.
- Put repo-specific conventions, commands, and deployment notes in this custom section so they survive vendored guidance updates.
- The project-facing name is `concierge`; the vendored C3 block may still mention the original scaffold command and template name for provenance.
- The MCP server exposes a single `code` tool backed by Cloudflare Code Mode `createCodemodeRuntime()` and repo-owned connectors. Execute MCP calls through the host-facing `runtime.execute()` API; use `runtime.tool()` only to derive the upstream model-facing description. `ConciergeMcpRuntime` hosts the Code Mode runtime/facet state; keep connector tools stateless unless they genuinely need Durable Object-backed session state.
- The MCP endpoint uses the MCP SDK v2 `McpServer` from `@modelcontextprotocol/server` with the stateless `createMcpHandler` from `agents/mcp/server`. Preserve its per-request server factory and default legacy compatibility; the Durable Object holds application/runtime state, not MCP protocol session state.
- MCP packages are pinned directly; the scoped `agents@0.28.0` npm overrides use those pins because Agents still declares exact older MCP peer versions. This combination is repo-tested, not declared supported by upstream. Revisit the overrides on every Agents/MCP update and remove them when upstream peer ranges permit the selected versions; keep clean installs with strict peer checks and the full MCP regression suite passing. Do not use global `--force` or `--legacy-peer-deps` to bypass conflicts.
- Explicitly declare `tools.listChanged: false` before registering tools; Concierge does not publish tool-change notifications. Do not inherit SDK capability defaults for unsupported features.
- After OAuth/debug gating, bound incoming MCP bodies to 4 MiB by actual streamed bytes, cancelling oversized streams before forwarding to the runtime. The `code` input schema caps source at Code Mode's 1,000,000-character limit; keep its advertised and enforced limits aligned with upstream.
- MCP OAuth uses Client ID Metadata Documents without Dynamic Client Registration. Keep `clientIdMetadataDocumentEnabled` and the required `global_fetch_strictly_public` compatibility flag in sync; do not add `clientRegistrationEndpoint` unless intentionally restoring DCR.
- Let OAuth Provider handle CIMD `none` and `private_key_jwt` client authentication. Preserve its assertion validation and replay protection; an invalid assertion must not fall back to public-client authentication. Keep regression coverage for both methods and clients advertising both choices.
- OAuth Provider requires the canonical resource `https://concierge.j1.io/mcp`; keep `resourceMetadata.resource` aligned with the public MCP endpoint. Local debug calls bypass OAuth and do not change this token audience.
- Use OAuth Provider's consent and upstream-login helpers for browser-bound transactions, remembered consent, and safe error redirects. Keep the consent page repo-owned, submit only its opaque handle and decision, and preserve the helpers' response headers. Do not restore custom CSRF/state signing or legacy approval-cookie fallbacks. In `src/access-handler.ts`, use `oauth4webapi` for Access PKCE, authorization-response parsing, token exchange, and ID-token validation; explicitly verify the RS256 signature with `validateApplicationLevelSignature`, retain zero clock tolerance and Concierge's audience/authorized-party restrictions. Skip the library's state check only after `finishUpstream` has validated and consumed the browser-bound transaction. Do not log or expose upstream OAuth error payloads.
- Verify Access ID tokens with `jose`, pinned to RS256, the issuer parent of the configured `ACCESS_JWKS_URL`, and `ACCESS_CLIENT_ID` as the only trusted audience. Require valid `exp`, `iat`, and nonempty `sub` claims, validate `azp` when present, and return sanitized verification errors. Do not restore manual signature-only validation.
- Keep the model-facing `code` tool description derived from the upstream Code Mode default, then sanitize unsupported project features locally; do not copy the whole upstream description unless intentionally pinning it.
- Keep the model-facing Tool Discovery section explicit that `codemode.search` searches connector method metadata rather than external content. Search task capabilities first, allowing platform names, and prefer a purpose-specific API over webpage reading when it supports the task. Queries should be short capability phrases and should be retried in simpler form when no method matches. Keep connector hints aligned with every active connector and its capabilities; do not use Google Maps webpage reading as the discovery example.
- Keep model-facing Failure Recovery guidance aligned with the shared connector policy: failed code does not undo earlier side effects, and unknown or successful write outcomes must not be blindly replayed.
- Cloudflare's `read_webpage_as_markdown` is a stateless live public-page reader, not an interactive or authenticated browser. Disable Browser Run's rendering cache (`cacheTTL: 0`), retain bounded readiness/selector waits and the shared deadline, and return source metadata with paged Markdown. Continuation reads render anew and require the previous content hash; reject changed content rather than mixing versions. Do not persist page bodies, expose origin headers, claim retrieval time is publication time, or treat webpage content as instructions. Gate-page detection is conservative and cannot guarantee every incomplete page is recognized.
- The MCP-facing `code` output schema wraps the Code Mode return value as `structuredContent.result`; keep the text `content` fallback aligned with the same value.
- Retain upstream structural result truncation rather than a custom fork. Model guidance should favor native pagination and projection before returning large values, preserve needed IDs/status/pagination in smaller results, and warn against treating truncated output as complete or reusing clipped identifiers/cursors. Test omission markers and text/structured parity on large lists as well as strings.
- Keep MCP tool annotations aligned with the active connector set. The current `code` annotations intentionally mark it as write-capable and destructive because Notion and Gmail expose broad writes/deletes.
- The Notion connector intentionally exposes one compact `notion.request({ method, path, query?, body? })` method instead of embedding or generating the full API schema. Models should consult the current official Notion API documentation for endpoint details before calling it.
- Notion API calls use the `NOTION_TOKEN` Worker secret and pin the `Notion-Version` header in `src/notion-connector.ts`; verify current Notion API versioning docs before changing that constant.
- Google Workspace lives in `src/integrations/google/` and exposes `google.request({ service, method, path, query?, body? })`. Gmail is currently enabled, including writes and settings; other Workspace services require explicit API enablement, Admin delegation scopes, and a server-owned service definition. Do not let callers choose credentials, scopes, API origins, or the impersonated user.
- Google authentication uses the `GOOGLE_SERVICE_ACCOUNT_JSON` Worker secret for `concierge@j1-concierge.iam.gserviceaccount.com`, signs RS256 JWTs with `jose`, and exchanges them for Workspace domain-wide delegated tokens with fixed `sub=joe@j1.io`. The service-account identity, token endpoint, and scopes are server-owned; do not restore WIF/mTLS or credential fallbacks.
- Never commit or log Google private keys, signed assertions, or access tokens, or expose them through tools. Delegated tokens are cached only in the Durable Object's private memory, with a refresh margin and concurrent exchange deduplication; they are not stored in KV or Durable Object storage. Rotate the Worker secret and revoke the old Google key together, with a live read-only MCP test. Verify the Google billing account remains active; it was upgraded to paid pay-as-you-go billing on October 3, 2026.
- Google API `401` responses invalidate the cached token; calls are not automatically replayed, including mutations. Authentication error bodies and tokens must never reach MCP output or logs.
- Google Maps is separate from Workspace in `src/integrations/maps/` and exposes `maps.request({ service, method, path, query?, body? })`. Places API (New) and Routes API share the `GOOGLE_MAPS_API_KEY` Worker secret. Places uses native `/v1/` paths; Routes permits POST `/directions/v2:computeRoutes` and `/distanceMatrix/v2:computeRouteMatrix`. Field masks belong in `query.fields` or `query["$fields"]`, never caller-provided credentials or API origins. Preserve API responses and attribution; do not add persistent Places content caching. Route matrices return native arrays with per-element status/condition and are billed per origin-destination element; include these outcome fields in masks. Only server-owned known read-only POST endpoints may receive read replay behavior. Maps requires its own API enablement, billing, API-key restrictions, and quota configuration; it does not use Workspace delegation.
- Put generic connector reliability in `src/connector-requests.ts`, not independent connector retry loops. All connectors share deadlines, bounded retries/backoff, `Retry-After` cooldowns, concurrency/queue limits, bounded response reading, sanitized errors, and metadata-only telemetry. Connectors supply authentication, allowed endpoints, tool contracts, and provider-specific error/replay classification; successful return values stay unchanged.
- Code Mode execution telemetry records only duration, runtime status, and connector-call count, including failures before any connector call. Never log submitted source, results, sandbox logs, exception messages, credentials, or personal data; telemetry failures must not change execution outcomes or trigger retries.
- Define connector inputs once with strict Zod schemas; derive Code Mode's Draft 7 JSON schemas with `z.toJSONSchema()` and validate calls with the same schema. Use `src/connector-inputs.ts` for shared REST fields and GET-body rejection; keep provider-specific schemas and URL/security rules in the connectors. Do not restore parallel handwritten schemas and argument parsers.
- Retry individual requests, never whole Code Mode invocations. Reads are replay-safe by default; writes require an explicit server-owned replay policy or a provider-confirmed rejection. Notion permits replay after documented 429/529 rejections except blocked access; Gmail 403 rate limits are distinct from permission failures and do not automatically replay writes. Recheck official provider guidance before changing these exceptions. Nested authentication helpers must not multiply retry budgets.
- Shared reliability state is private, transient memory on `ConciergeMcpRuntime`, not persistent quota accounting. Defaults are a 30-second total deadline, at most two retries, four concurrent operations and 32 queued per provider, and 4 MiB successful/8 KiB error response limits. Browser Run uses 45 seconds and token exchange 20 seconds. Include queue/auth/body reading in deadlines; keep permits for non-cancellable binding work until it settles. Surface write outcomes (`not_started`, `rejected`, `unknown`, `succeeded`) and never imply a timeout rolls a write back.
- Do not mark connector tools with `requiresApproval`; this MCP server does not expose Code Mode approval/resume controls, so approval-required runs are treated as errors.
- Do not rely on Code Mode rollback/revert for MCP-visible behavior; this server does not expose rollback controls, and arbitrary side-effect tools should be designed as explicit safe operations instead.
- Do not advertise `codemode.step` in the model-facing tool description while replay/resume-oriented workflows remain unsupported.

- `npm run dev` uses Vite on port 8788. The Vite config enables `CONCIERGE_DEBUG` only for dev, never in build output or `npm run preview`. Keep binding names, Durable Object classes/migrations, secrets, and routes in the Wrangler input unchanged across bundler updates.
- `npm run dev` enables `CONCIERGE_DEBUG=true` and exposes the authless local MCP route at `http://localhost:8788/debug/mcp`; production `/mcp` remains OAuth-protected.
- `npm test` runs the production Worker bundle through Wrangler's integration test harness. It covers the OAuth boundary, CIMD consent/code exchange/token refresh, browser binding, denial, transaction replay/expiry, remembered consent, concurrent logins, debug-route gating, Host/Origin validation, modern and legacy MCP flows, structured Code Mode truncation, and all active connectors.
- `npm run build` runs the type check, integration suite, Vite build, and generated-configuration parity/compiled-MCP smoke tests. `npm run deploy` builds first, then uses Wrangler with `dist/concierge/wrangler.json`; never deploy the source config instead of the generated bundle. `npm run cf-typegen` explicitly reads the input configuration.
- GitHub CI validates type generation, checks, tests, Vite build, and a generated-config Wrangler dry-run. Workers Builds is independent: before production rollout, verify root `/`, production branch `main`, build command `npm run build`, and deploy command `npx wrangler deploy --config dist/concierge/wrangler.json`. `.node-version` selects Node 24 for CI and Workers Builds. Keep production untouched until those external settings are verified; do not assume GitHub CI gates Workers Builds.
- Workers Builds was verified for the approved production rollout on 2026-10-03: production branch `main`, root `/`, build command `npm run build`, deploy command `npx wrangler deploy --config dist/concierge/wrangler.json`, no build variables, and preview branch builds disabled. The explicit generated-config deploy command was saved and verified in the dashboard before merging the migration.
- The integration suite uses test-only secrets, replaces Browser Run with a local test Worker, and mocks Google, Notion, Access, and CIMD requests; it does not require local credentials or make live connector calls. Google tests cryptographically verify signed JWTs and cover fixed delegation, credential validation, token caching/expiry/concurrency, credential isolation, endpoint validation, JSON writes, and failed mutation handling. Reliability tests cover safe/unsafe replay, provider exceptions, nested auth retry budgets, deadlines, bounded/cancelled streams, error redaction, cooldown guidance, and concurrency across MCP calls. A test-only fixture exercises short deadlines without adding production configuration or routes. Use direct test Worker dispatch with the canonical production origin for OAuth discovery and authenticated requests.
- The integration suite is the repeatable regression gate; it does not replace MCP Inspector for manual local client testing and exploratory tool calls.
- Generate oversized ingress bodies in a test Worker and send them through a test-only service binding; early upload cancellation can reset the harness HTTP socket before a response arrives. Keep stream-cancellation and exact-byte boundary assertions. Wait for observable logs or work completion instead of assuming fixed sleeps are sufficient; do not retry away failures or weaken production limits to accommodate tests.
- With `npm run dev` running, use `npx --yes @modelcontextprotocol/inspector --cli http://localhost:8788/debug/mcp --transport http --method tools/list` to inspect the local server, then use `--method tools/call --tool-name code --tool-arg code="..."` to invoke a tool manually.
- Live Google local calls require `GOOGLE_SERVICE_ACCOUNT_JSON` in the ignored `.dev.vars` file or process environment. A read-only smoke call is `code="async () => await google.request({ service: 'gmail', method: 'GET', path: '/gmail/v1/users/me/profile' })"`. Use `npm test` for credential-free regression checks.
- Live Maps local calls require `GOOGLE_MAPS_API_KEY`; when using process environment with Vite, set `CLOUDFLARE_INCLUDE_PROCESS_ENV=true`. Test `maps.request` through the local MCP route with a small Places search and an explicit `query.fields` mask. These read-only calls can incur charges; never print the key or persist API results.
- Use `/debug/mcp` only for local tool iteration; use `https://concierge.j1.io/mcp` when validating the real OAuth client flow.
